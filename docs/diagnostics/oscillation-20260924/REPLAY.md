## 可重复实验

从仓库根目录执行（不连接模型、网络或正在运行的仿真）：

```bash
mujoco_demo/.venv/bin/python \
  docs/diagnostics/oscillation-20260924/replay_mpc.py \
  --recording docs/diagnostics/oscillation-20260924/recorded_paths.json
```

使用生产 `MpcTracker._solve` 和 `build_pose_aligned_reference`，保持原 MPC 参数。按 100 ms 控制周期、5 ms 运动积分运行虚拟时间 20 秒；位置积分采用与 TurtleBot 相同的中点航向公式。求解输出固定延迟 30 ms 生效，并按生产逻辑丢弃已被新路径替代的求解结果。初始角速度为 0。

这是确定性的控制器隔离实验，不是包含渲染、线程调度和视觉反馈的完整 MuJoCo 重跑。路径更新时，用回放自身历史中的采图位姿将局部路径投影到世界坐标。

录制路径来自上次修改前基线的运行。更新到达时刻由约 50 ms 采样的状态首次变化估计，采图时刻由到达时刻减去推理耗时近似；并非原始逐帧精确采图记录。故主要依据受控的固定路径/恒定局部路径实验，不把录制回放宣称为原现场逐步复现。

## 结论与原理

在这些条件下，MPC 跟踪固定世界路径可以收敛，没有发现固定参考下自行持续振荡的证据。但这并不证明该 MPC 在所有曲线、延迟和速度下都稳定。

主要证据指向**延迟的局部路径更新与控制器构成的反馈振荡**，而非必须由模型交替输出左转/右转引起。连连续相同的局部直行指令，在 0.65 秒历史位姿锚定下也会出现明显反复转向。

机器人在推理等待期间继续运动；结果到达后，路径按采图时的旧朝向正确投影到世界坐标，控制器又试图拉回这条相对于当前位置已落后的参考。当前 MPC 预测窗口为 0.5 秒，而观测到的推理耗时约 0.6–0.8 秒。反复更新历史参考，配合较大的转向权限，会形成过冲和反向修正。本次受控实验支持这一机制，不证明它是所有现场异常的唯一原因，也没有测出普适的延迟稳定阈值。

**不能将“把旧路径直接按当前位姿投影”当作修复。** 零延迟实验只是反事实对照；真实图像的坐标变换仍必须使用其真实采图位姿，否则空间语义错误。

后续应在保持采图坐标对齐的前提下验证路径时效性、旧路径有效区间与新旧参考切换，必要时按延迟降低速度/转向强度。先用本回放评估，再做完整模型闭环验证。本次只完成诊断，未修改生产 MPC 参数或控制行为。

## 后续降速试验

按用户要求，将 `mujoco_demo/vln_mujoco/mpc.py` 的导航速度上限 `OBJNAV_V_MAX` 从 0.8 改为 0.4 m/s、共用角速度上限 `W_MAX` 从 3.0 改为 1.2 rad/s。其他 MPC 权重和加速度参数未改。前述表格记录的是降速前的参数；此后重新运行回放脚本会使用新参数。

相同录制路径回放最后 10 秒，角速度峰值从 2.548 降为 1.2 rad/s，方向反复次数从 10 变为 14。恒定局部直线、0.65 秒延迟组的峰值从 1.953 降为 1.156 rad/s，反复次数从 13 变为 15。说明本次限速限制了动作强度，未消除振荡，不能宣称控制稳定性已修复。新时序保存为 `reduced_speed_results.json`。

### 页面 LATENCY 与 SSH 的区别

`vln_client.py` 在发送 `next` 请求前记录单调时钟，收到并解析模型结果后计算 `latency_ms`；计时包括编码/发送、模型服务等待与处理、回包解析，不包括结果经浏览器 SSH 隧道显示所花的时间。当前 MuJoCo 直接访问同一服务器的 `ws://127.0.0.1:8050`，而 SSH 仅转发浏览器到 8088。

`offer_frame` 在待处理槽位非空时拒绝新帧；前一轮推理期间缓存的帧可能先等待，再发送。因而页面 LATENCY 并不是从采图到执行动作的总延迟，不能将 400 ms 直接当作图像年龄。上述旧回放用推理耗时近似图像延迟，也没有纳入这段等待，后续应补录精确时间戳验证。
