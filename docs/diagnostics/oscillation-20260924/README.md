# 左右振荡对照记录（2026-09-24）

## 实验

基线：从当前仓库 `HEAD:mujoco_demo/vln_mujoco/server.py` 读取增加轨迹图之前的服务代码，动态加载；当前组使用工作区服务代码。两组均使用当前相同的底盘、MPC、依赖和运行中的 8050 模型服务，各自创建独立 MuJoCo 仿真、从默认起点开始，顺序运行 25 秒。没有重置用户正在使用的 8088 仿真。

指令取此前页面截图：`move forward, then go to the green trashcan on the right`。两组都模拟约每 90 ms 请求两路摄像头；当前组额外每 200 ms 请求轨迹图。每约 50 ms 记录实际位置和速度命令。

## 结果

| 指标 | 修改前服务 | 当前服务 |
| --- | ---: | ---: |
| 显著角速度方向切换次数（忽略绝对值 ≤ 0.25 rad/s） | 18 | 18 |
| 最大角速度绝对值 | 3.0 rad/s | 3.0 rad/s |
| 推理耗时中位数 | 628.9 ms | 646.8 ms |
| 轨迹采样耗时中位数 | 不适用 | 0.098 ms |
| 轨迹采样耗时最大值（包含等待仿真锁） | 不适用 | 17.55 ms |

两版都出现明显的左右转向反复；两次轨迹并不相同。见 `comparison.png` 和两份 CSV。

## 可以得出的结论

- 在本次环境和指令下，不含新增轨迹代码的基线也能复现振荡，新增轨迹功能不是该现象出现的必要条件。
- MPC、底盘运动、模型客户端文件没有工作区改动；依赖锁文件只增加本地轨迹包，没有改变已有依赖版本。
- 轨迹记录只读取仿真位姿、减去起点位置并画线，不向控制器输出路线或速度。
- 模型约 0.6–0.8 秒更新一次结果，MPC 按 0.1 秒周期跟踪。当前原有配置允许 3 rad/s 角速度、5 rad/s² 角加速度。慢速路径更新与较强的转向修正可能造成过冲、反向修正，但本次实验尚未隔离各因素，不能认定它们就是唯一根因。

## 限制和后续

这是各一次、25 秒的诊断，不是统计性能对比。转向次数包括正常转弯，不是独立的振荡严重程度指标。基线指当前 Git HEAD，并不证明与用户过去运行时的模型状态、系统负载、指令及源码版本完全一致。实验期间用户原有仿真仍在运行，两组均在这一背景负载下测量。

没有为了让图看起来更平滑而过滤真实轨迹，也没有调整 MPC 参数。要进一步定位并修复，需记录每次目标路径更新、MPC 参考点、采图位姿与实际转向的对应关系，再使用固定路径/固定输入回放分别测试控制器过冲与模型重规划的影响。
