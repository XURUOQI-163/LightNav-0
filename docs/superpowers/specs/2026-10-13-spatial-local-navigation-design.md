# 5 米空间窗口局部占据地图与 waypoint 修正设计

状态：设计稿，供确认；尚未实现、尚未验证 Isaac 实景效果。

## 1. 已确认的需求

在现有 Isaac / Carter 导航页面中增加以下链路：

```text
RGB-D + 同时刻位姿 → 短期局部占据地图
                              ↓
当前车体 footprint → 障碍膨胀与碰撞检查
                              ↓
LightNav 原始路径 → 局部路径修正 → 跟踪器 → 执行前碰撞检查
```

- “短期”仅指空间局部性：以当前小车为中心，半径默认 5.0 米的圆形窗口；不是 5 米直径。
- 半径可配置。窗口随车平移，保留仍在窗口内的观测；不按秒数、帧数、TTL 或指数时间衰减删除证据。
- 原始预测 waypoint 和修正路径用不同颜色，实时叠加到同一局部占据地图。
- 保留 LightNav / OmniVLA 模型、原始输出、现有三路图像、房间记忆与语义识别。
- 本阶段不切换官方 MPC，不更换模型输出头，不引入雷达、SLAM、全局稠密点云或物体实例图。
- 第一版接 Isaac GT pose；算法核心只接收统一 RGB-D / 位姿 / 相机 / footprint，不导入 Isaac。

## 2. 当前代码事实与接入边界

1. `habitat_demo/room_memory/structure.py` 的 `coverage` 表示看过的区域，不表示机器人可通行；`walls` 主要保存高立面证据，不完整保留低矮家具。因此不能把 Room Region 的范围填色直接作为避障空闲区。
2. `isaac_demo/isaac_web/scene.py::_capture()` 已返回同一时刻的 RGB、光轴 Z 深度（米）、相机内外参、地面投影 GT pose。复用这一观测，不另开相机。
3. `isaac_demo/isaac_web/robot_profiles.py` 已统一两个车体配置：

| 配置 | footprint 长度 | 宽度 | 高度 |
|---|---:|---:|---:|
| original | 0.710 m | 0.630 m | 0.663 m |
| half_xy | 0.355 m | 0.315 m | 0.663 m |

footprint 相对 base 原点前后不对称，必须读取四个实际顶点，不能假设原点在矩形中心。
4. `habitat_web/control.py::command_for_path()` 以一个前瞻点计算速度，不保证严格沿折线行驶。因此路径修正之后仍要检查控制指令产生的运动。
5. 当前 Isaac 为“观测 → 模型推理 → 有限步运动 → 新观测”的顺序循环。第一版保持该时序；等待推理时物理不继续推进。地图使用每次有效导航 RGB-D 更新，不把仅用于显示的预览帧伪装成新深度观测。

## 3. 5 米圆形空间窗口

### 3.1 坐标和大小

- 世界坐标 X/Y 为水平面、Z 向上；局部机器人 X 前、Y 左，yaw 逆时针为正。
- 默认分辨率 0.05 米。内部使用覆盖圆形窗口的栅格方框；实际有效域满足 `distance(cell, current_robot) <= 5.0 m`。
- 有效圆面积约 78.54 平方米，约 3.14 万个栅格；内部数组约 201×201，并可增加少量对齐保护格。
- 栅格朝向固定在世界坐标，不随机器人转向旋转。索引用稳定的世界栅格坐标；换窗口只移动索引和圆形掩码，不旋转、插值旧占据值。
- 窗口中心使用最新位姿；不能只在完成一次整格平移后才更新圆形有效域。

### 3.2 保留与删除规则

| 情况 | 结果 |
|---|---|
| 小车原地停留 | 不因时间过去删除障碍或空闲证据 |
| 小车平移，某格仍在 5 米内 | 保留该世界位置的证据 |
| 某格离开 5 米窗口 | 从局部地图丢弃，不在环形缓存中保留可再次读到的旧值 |
| 之后返回曾被裁掉的区域 | 从未知开始，重新观测 |
| 新深度确认以前的障碍位置已经空出 | 使用新的自由空间证据清除障碍，不等待超时 |
| 原障碍暂时出现在视野外、深度无效或被遮挡 | 不把“没看见”当成“已消失” |
| 重置、切场景、位姿跳变或楼层失配 | 清空局部地图和执行路径，等待新有效观测 |

传感器断流、数据序号不匹配、求解超时仍可触发停止。这是执行有效性检查，不能借此按时间清空地图。

## 4. RGB-D 到可通行证据

### 4.1 输入与同步

输入包携带 `observation_id, session_id, sim_time, rgb, depth, pose, K, camera_to_robot`。
所有字段来自同一次 `_capture()`；不能用网页当前位姿解释之前的模型输入图像。
LightNav 的 `[forward, left, yaw]` 使用输入图像采集时的机器人位姿转换到世界坐标，原始数组不改写。

### 4.2 障碍和空闲

- 去掉无效、非有限、越界深度；深度以光轴 Z 而非射线距离解投影。
- 在车体碰撞高度范围内保留墙、门框、柜体、椅子等碰撞证据；下界避开地面噪声，上界由实际车高和余量决定。
- 地面回波用于地面支持及空闲估计，不作为障碍。缺深度、楼梯落差或缺少地面支持不能直接填为空闲。
- 按相机射线更新已观测空闲区和障碍终点，不填充“最远射线包围的整个扇形”作为可通行区。
- 一个水平格中存在障碍证据时，不能被从其上方经过的射线直接清空。内部可保留小型高度分箱证据用于清除判断，输出仍是二维栅格；不保存原始点云或完整三维地图。
- 同帧障碍优先于空闲，未知保持独立状态。障碍清除需要新射线实际穿过对应高度区间，连续有效观测确认；该确认用于去噪，不是按观测年龄过期。
- 出生时仅允许以验证有效的当前车体占据范围建立起始种子，不能把周围一个圆盘假定为空闲；若当前 footprint 已与观测障碍重合，则上报起始冲突。
- 不读取 USD 全场景障碍真值填图，不使用房间分类结果判定通行，不把房间分割用的虚拟 Portal 切线当作实体墙。

输出至少包含 `unknown / free / occupied`。这是基于前向深度的可通行估计，不是对不可见障碍的保证。
玻璃、反光、薄障碍、采样间隙和盲区保留为观测限制，不能声称获得了完整 360° 障碍检测。

## 5. 膨胀和 footprint 碰撞

- footprint、车高和相机安装参数直接来自当前选中的 robot profile；不再在导航模块手写另一套尺寸。
- 增加独立的 `safety_margin_m`，设计初值 0.05 米；配置验证需明确它是每侧余量。
- 硬限制：实际 footprint 加余量后覆盖的栅格不得碰到障碍；执行路径不得进入未知或窗口外。
- 软代价：在硬限制之外增加可配置的近障惩罚，倾向于走宽敞位置；不能把整片软代价区域全部判为不可通行。
- 固定朝向的膨胀核为带余量 footprint 的反射形状；转向时必须按朝向重新检查。不能仅用半车宽代替四角碰撞。
- 地图绘制的硬膨胀层明确标注“当前朝向”。搜索和执行检查考虑整段轨迹中的不同朝向；当前朝向的二维膨胀图不能当作所有转向的通行保证。
- 对车体扫掠进行插值采样：平移步长不大于半个栅格，旋转步长使最远顶点位移不大于半个栅格；栅格离散误差计入检查余量。
- footprint 整体必须位于有效观测窗口内；不是中心仍在圆内就允许车身伸进窗口外。
- 5 米窗口内不在当前视野中的历史证据保留。动态障碍若从背后进入仍可能漏检；首版不开放依赖未知后方空间的自动倒车绕行。

## 6. 原始路径检查与整段修正

### 6.1 原始预测不可变

保存原始 waypoint 及其 1–10 序号；模型实际少于 10 点时按实际数量显示，不补造。
分别记录点和相邻段的状态：`clear / occupied / unknown / outside_window`。
点本身安全不代表点间连线安全；从当前车位到第一个参考点也要检查。

### 6.2 推荐方法

采用受限的局部路径搜索，而不是逐点找最近空地：

1. 将原路径变换到世界坐标，在本次地图快照上检查。完整可行时保留原路径。
2. 有冲突时，从当前车体状态出发，沿原预测的前进顺序寻找可达的局部目标。目标优先考虑原路径后段的有效点，再考虑其附近有限距离内的候选自由位置。
3. 使用带朝向状态的局部 A* / 状态格搜索，运动原语包含前进、有限曲率转弯和原地转向；每条原语都执行 footprint 扫掠检查。第一版默认不自动倒车。
4. 路径代价结合行驶距离、与原始预测折线的偏离、靠障碍程度、转向幅度和转向方向切换；避免只靠最近距离把目标吸到墙另一边。
5. 设定最大目标修正距离、最大绕行距离和搜索工作量。初值分别为 0.75 米、原参考长度加 2.0 米、最多 20000 个展开状态；这些是实现初值，不是已验证的最优参数。
6. 只接受从当前状态连通可达的目标。平滑和重采样后必须重新检查整段轨迹，不能平滑后切穿门框。
7. 原始 10 点全部失效时，仍可在限定偏离范围内找到安全绕行；否则返回有正向进展的安全前缀或明确停止，不无限扩大搜索范围去替模型做全局规划。

搜索队列中的位置、朝向和连续运动原语必须一致；不能只做二维点 A*，结束时才给每点随意填一个 yaw。
同一目标附近若左右绕行代价相近，可优先保持上次仍有效的绕行侧；障碍改变使其失效时立即放弃，不能为稳定显示保留危险旧路径。

### 6.3 输出与跟踪器接口

`CorrectionResult` 包含：

```text
session_id, prediction_id, capture_pose, map_revision
raw_world_waypoints, raw_point_status, raw_segment_status
corrected_world_path（x、y、yaw），status，reason
target_world_pose，planning_ms，used_prefix
```

状态为 `unchanged / corrected / safe_prefix / blocked / waiting_observation`。
修正路径点数按几何需要决定，可以多于或少于 10；不要求修正点与原始点一一配对。
执行用的路径单独提供给跟踪器，`raw_waypoints` 继续用于预测图像和对比显示。
官方 MPC 将来可接同一修正路径接口，本阶段不实现 MPC 切换。

## 7. 执行前检查与失败处理

- 本阶段保留当前有限步执行节奏。必须在每次 `step(v, w, dt)` 之前，根据当前位姿检查该控制指令实际产生的圆弧 / 原地转向，不能只检查参考折线。
- 以有界减速候选和可行转向候选筛选控制输出，并重新检查完整扫掠；仅减速仍不安全则输出零速度，报告 `blocked_command`。
- 检查包括到本次步进结束和制动余量的运动包络；实际动力学跟踪误差由余量覆盖，验收时必须核查。不能把运动学预测当作绝对物理无碰撞保证。
- 不允许非零速度进入未知、窗口外或碰撞区域。地图缺失、输入不匹配、搜索超时、地图版本过期时停止并上报具体原因。
- 与地图相关的计算在单独有界工作线程执行，主线程拿一致快照；STOP、RESET 和新 session 使旧结果失效。完成规划后若位姿或地图已变更，执行前重新验证，不能直接发送旧结果。
- STOP 总是可用；启用避碰时有限手动运动也经过相同执行检查，避免页面的手动按钮绕过保护。
- 找不到安全前缀时不持续让车顶墙，也不在后台无限重试模型。任务以明确状态暂停/停止，页面保留失败图供分析。

## 8. 页面：一个局部地图内同时看原始与修正结果

在现有页面增加“局部占据地图 · 半径 5.0 m”面板；房间语义图原样保留。
局部面板不依赖 `--room-memory` 或 CLIP：关闭房间记忆仍可显示局部避碰地图。

| 图层 | 显示 |
|---|---|
| 未观测区域 | 灰色 |
| 已观测空闲区域 | 浅色 |
| 障碍栅格 | 深色 |
| 当前朝向的硬膨胀区 | 半透明橙色 |
| 近障软代价 | 较淡渐变，可隐藏 |
| 原始 waypoint | 蓝色点，编号 1–10，虚线连接 |
| 原始碰撞点/段 | 蓝点外加红圈 / 对应段红色覆盖 |
| 未知或窗口外原始点 | 黄色状态提示，不假装是碰撞点 |
| 修正轨迹 | 绿色实线，明显箭头和末端标记 |
| 被执行的短时运动 | 独立箭头，便于区分“参考路径”和“实际控制” |
| 小车 | 当前 profile 的实际 footprint 轮廓及朝向 |

- 图例常驻；颜色之外还用线型和文字区分。
- 地图保持世界方向，车在圆心；转向不让整张图旋转。
- 原始和修正路径使用同一世界坐标及同一缩放，不用修正结果覆盖原始数据。
- 超过 5 米的预测不扩大地图或被伪装成边界 waypoint。真实越界部分裁剪，并显示“窗口外 N 点”；边界方向提示与真实点使用不同符号。
- 显示当前半径、分辨率、profile、余量、有效原始点数、修正状态、规划耗时和受阻原因。
- HTTP 只读取不可变快照，不触发建图、渲染或运动。地图图层、原始路径、修正路径携带一致版本；若显示较早的规划结果，明确其地图版本，不能伪称是最新验证结果。
- 前端目标刷新率默认 5 Hz，有新版本才更新，不排队播放旧地图。刷新率不改变物理步长或模型推理频率。
- “模型输入与预测点”图像继续显示原始模型输出；修正路径首先只叠加在本局部地图，避免混淆模型原始能力与修正层效果。

## 10. 验收与性能边界

先进行无 GPU 合成测试，不启动用户的现有终端或昂贵场景；后续单独进行最小 Isaac 实景验收。

1. 同位置推进时间，地图不衰减；窗内旧障碍不消失。
2. 位姿跨格、亚格移动、只旋转时，世界位置和圆形掩码正确；无环形缓存回卷旧障碍。
3. 离窗裁剪，重新进入为未知；深度有效范围超过 5 米也不扩大地图。
4. 墙、低障碍、地面、无效深度、不同高度射线与障碍移除，验证空闲更新不穿透已知障碍。
5. 原尺寸/half_xy、非对称 footprint、转弯扫掠分别测试；同一道窄门可能只允许小车通过。
6. 路径端点安全但中段穿墙，必须检出；隔墙最近空地不得直接吸附过去。
7. 全部原始点碰撞时，可行绕行能找到；无可行路径必须零速度并给出原因。
8. 原始路径安全时不无谓修改；未知区、5 米边缘、足迹越界都按既定策略处理。
9. 平滑、重采样、现有跟踪器切角和原地转向的执行碰撞全部覆盖。
10. 图像采集时位姿与模型返回时位姿不同、地图更新、STOP/RESET、session 切换，旧结果不得驱动车辆。
11. 页面同时显示原始 10 点和修正路径；profile、颜色、地图坐标、越界提示及地图版本一致；关闭 Room Memory 仍可显示。
12. API 刷新不推进物理，显示队列不积压；统计建图/搜索耗时及内存，确认空间窗口大小不随运行时间增长。

5 Hz 是页面目标刷新率，不是已测性能承诺。实际建图与修正吞吐取决于 RGB-D 产生频率、采样密度和搜索工作量。
搜索达到工作量上限或运行预算时，返回明确失败/安全前缀，不能为维持运动而跳过碰撞检查。
