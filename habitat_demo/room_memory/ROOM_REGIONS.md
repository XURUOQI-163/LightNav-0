# 前向 RGB-D 房间范围（2026-10-07）

当前阶段使用 Habitat GT pose，不安装 RTAB-Map，不修改 LightNav/OmniVLA 推理、速度、控制器或原门口检测阈值。默认 `--room-memory` 同时开启区域观察；`regions.enabled=false` 只关闭范围构建，原节点、轨迹、门口和 Places365 继续运行。

## 输入和分工

`RGBDFrame` 的同步 RGB、米制轴向 depth、`PoseSource` 位姿和 `CameraModel` 外参保持原接口，新增可选 `elevation`（机器人原点的世界高度）。Habitat 适配器提供 `pose.y`；其他适配器可提供 `floor_elevation`。当前投影假设机器人底座水平，倾斜相机由固定外参处理；动态机身 roll/pitch、跨楼层和 SLAM 回环尚未实现。

| 文件 | 职责 |
| --- | --- |
| `structure.py` | 参数校验、深度降采样/反投影、有限二维覆盖与重复墙体证据 |
| `regions.py` | 在已观测覆盖内按墙段、Portal 和房间种子分区，提取外轮廓/未知孔洞 |
| `graph.py` | 在原图上附加范围，迟到 Portal 到达后重新分区，持久化 |
| `service.py` | 复用有界观察线程和 session；导航不等待建图 |
| `habitat_web/web/room_map.js` | 彩色区域、边界线、面积、选择和显示开关 |

## 算法与证据含义

1. 降采样深度，过滤空洞、非有限值及配置量程外测量。在相关高度带内，每列使用实际看到的最远投影，邻列扇形取较短半径，避免跨深度跳变填补遮挡后方。这里只表示某个水平位置在某个高度被看到，**不表示地面可通行**。
2. 临时三维采样按水平位置分组；高度跨度、顶部高度、相邻延伸满足条件，且在多个更新帧重复出现时，作为墙体证据。低矮桌椅通常不形成墙；高柜、密集装饰仍可能误判，尚无墙面语义分割模型。
3. 内存只保留固定大小的覆盖和墙体计数二维数组。地图围绕首次位姿建立，超范围停止接纳边界外数据并显示提示；不静默扩大到无限地图。
4. 在区域分割层，有限宽度的 Portal 线段切断两侧连接。原有“看到门即建候选、真实跨门后原 ID 晋升”不变，区域计算不能创建房间、改变类别或发动作。
5. 用正式房间入口/轨迹和候选房间门后锚点作为种子，沿已观测栅格做多源区域扩展。墙体与 Portal 阻挡扩展，未知格不参与。跨门迟滞范围里的旧房间轨迹点不作为错误侧的种子；原异步门检测仍负责修正已确认穿越后的轨迹归属。
6. 每次结构更新或 Portal/房间状态改变后重新分割，使晚到的门检测也能重新划分已记录区域。提取真实栅格轮廓，允许多个断开的片段，保留未观测孔洞，**不使用凸包补齐房间**。

大块未知孔洞仍可能显示为空白；它们不是物体实例或可用导航障碍图。反之，色块覆盖低矮家具上方的投影也不代表机器人能穿过家具。没有长期保存普通物体占据层、物体坐标、原始深度或全局点云。

墙体证据不等于建筑墙体真值。有限相机视角、门口漏检、家具遮挡、不同门通向同一空间、开放式客餐厅，仍可能造成轮廓不完整或分区错误。页面是任务过程中积累的部分空间记忆，不能作为已完成的建筑平面图或碰撞地图。

## 页面和 JSON v3

- 每个 Room 的颜色由 ID 稳定生成；名称继续来自 Places365，分类证据不足保留 unknown。
- 彩色区域是已归属范围；虚线是未闭合边界，实线覆盖有墙体支持的边界部分；蓝/红 Portal 保持原意义。
- “显示房间范围”只控制当前浏览器绘制。停止后台几何计算需设置 `regions.enabled=false` 并重启 Habitat。
- `region_polygons`：列表，每项包含世界 XY 米制 `outer` 和 `holes`，支持断开的可见片段。
- `boundary_segments`：带 `a/b/kind` 的边界证据；`kind` 为 wall 或 portal。其他边界由轮廓虚线表示。
- `region_area_m2`：当前归属栅格面积，**不是完整房间面积**。
- `boundary_state`：`unobserved`、`partial` 或 `enclosed`。enclosed 仅表示当前区域边界都有墙/门支持，不表示搜索完成。
- `geometry_confidence`：有墙/门支持的边界长度比例，不是校准概率，也不是房间覆盖率；语义置信度另存。
- 顶层 `structure`：开关、状态、地图原点、分辨率、覆盖面积、更新计数、最近区域构建耗时和错误。

`graph.json`、JSON 下载和网页使用同一数据。旧 v2 快照仍能显示原节点/轨迹；没有区域字段时不绘制区域。

## 参数、持久化与开销

所有参数在 `config/default.json` 的 `regions` 下，可独立调整。默认 0.05 m × 1024 格，即起点周围约 51.2 m 的正方形；覆盖和墙体计数原始数组各约 1 MiB，区域分割时还需临时缓冲。**这不是整个程序内存的上限。**

`update_interval=0.75` 按仿真时间节流；新 Portal 或晋升可能额外触发分割。观察和语义队列仍然有界、丢弃旧待处理帧；异步不是零开销，CPU 争用仍需实测。算法只用已有 NumPy/Pillow，未增加 OpenCV/scipy/SLAM 依赖。

每个 session 新增 `structure.npz`，仅包含 `coverage`、`wall_hits`、`origin`、`cell_size`、`revision`。graph/structure 各自原子写入，但不保证两个文件作为单个事务同时落盘。它们用于诊断和后续结构复用；本版仍不支持跨 session 恢复地图。

机器人高度相对本 session 初始高度变化超过 `floor_tolerance=0.35 m` 时，暂停区域更新并提示。**这不禁止机器人上楼，也不会把原拓扑模块升级为多楼层系统。** 建议先用 `00770` 同层场景，跨层实验暂不依据该图作结论。

以后接 RTAB-Map 时需要实现新的 PoseSource、动态姿态转换、位姿修正/子地图重投影机制；不能只把 SLAM 的 XY 接进来就认为支持回环。当前不声称完成这些实车接口的实现。
